02state traps (Quint)

Quint models live in explainers/ky-architecture/quint/. Each row is an invariant, whether the simulator broke it, and the rule it forces. Evidence is random simulation plus exact replays, not proof: quint verify needs Java 21 and this machine has 17. The models assume a FIFO socket, one clock shared by the node and the DO, and that pi-durable re-invokes a tool with the same call id after eviction. Full write-up: quint/README.md.

03Fable's review: recommendations and gaps

  • No Jobs table. ky_tasks already keys delegated work by an idempotent id (tasks.ts INSERT OR IGNORE). Fix its overloaded session/worker columns instead.
  • Node work stays out of pi tasks. A pi task can only park while waiting on other tasks; its sleep dies with the invocation. Multi-hour Claude Code sessions fit the inbox and feed better.
  • Node tools block with a deadline. A tool call is already a durable task, and a crash gives the model an interrupted result (pi-durable README:168). Anything longer than about 2 minutes is a node task. Quint disagrees on the default: both shapes are safe, but blocking also depends on pi re-invoking the tool with the same call id after eviction, so it prefers "started, then report later". A reasonable split is to block only for quick, bounded tools.
  • Node models stay on tunnels. Streaming over the runner WS would keep the DO awake and share a socket with tasks. Add a second vpc_services entry instead.
  • Automations use the Agents Scheduler. It's a Lifecycle capability and ky already runs Lifecycle. No backfill of missed slots; it's marked experimental.
  • One token for everything. KY_TOKEN is in every Claude Code child's env under bypassPermissions, so a prompt-injected task holds full UI access. Add KY_RUNNER_TOKEN.
  • Node name collisions. Two runners with the same name share a tag, and every command is sent to both (machines.ts:138-150).
  • Manifest versioning. Add one protocol integer. Schemas live in the DO and handlers on the node; a stale runner answers "unknown tool".
  • Side-effect ownership. Node tools should be main-only (add them to mainOnly) so a subagent can't create reminders.
  • UI submits carry no id (use-pi-session.ts:154-157), so a resend after a drop can double-submit. Found by the map subagent.

04the path, each step shippable alone

  1. Harden the runner protocol: the six Quint fixes. Flush the outbox before hello; fence reports by turn with a deterministic operationId; persist handled seqs; make stop() safe; let hello close queued tasks too; deliver pending rows in seq order. Also give each node name one socket.
  2. Manifest + split auth. hello carries {protocol, os, tools, models}, stored in ky_machines; add KY_RUNNER_TOKEN.
  3. Node tools. Add call / return / stop-call frames, a nodeTool() helper and apple_reminders, main-only.
  4. Automations. automations.ts, the Scheduler on Lifecycle, and one fire callback that submits to the main chat.
  5. Extract models.ts. A per-tunnel provider factory. The second node's model is then one binding plus one line.
